# 患者流程（PATIENT-FLOW）

> 规则（ZERO-TO-DEV §1.1）：页面树由三条真实流反推，不从医生流程照搬。
> 每条流写「患者在什么时刻最难受 → 打开哪一页 → 得到什么产物」。
> 状态：M1 调研后填实；本文先钉流骨架与双主体注意点。

## 流一：一次确诊就诊（新诊断，术后拿到病理+分子报告）

- 时刻（草案）：术后病理与基因检测结果到手，"IDH 野生型""MGMT 未甲基化"读不懂，下一阶段治疗选择迫近。
- 打开（草案）：我的瘤 · 分子档案 → 每项三态 + 人话解释 + 检测日期/方法。
- 产物（草案）：带去的分子档案摘要 + 问医生问题清单。
- 双主体注意：解读页对患者用大字白话，对照护者提供"逐项勾选已问过"。

## 流二：一次自查/日常记录（治疗期，家中）

- 时刻（草案）：TMZ 服药日血象低乏力 / 电场贴片部位头皮刺痒 / 疑似一次短暂发作没人说得清。
- 打开（草案）：指标分析（血象卡）· 电场档案（佩戴时长/皮肤反应）· 癫痫事件轨道（单次卡片）。
- 产物（草案）：当天记录 + 症状与激素并排时间线。
- 双主体注意：代记人身份记录发作；私密记录（心理/照护感受）默认 private。

## 流三：一次复查（随访 MRI 之后）

- 时刻（草案）：报告写"术区强化范围较前增大"，全家陷入假性进展还是复发的恐慌。
- 打开（草案）：随访影像页（本次与历次 MRI 并列：结论/激素用量/KPS）→ 问题清单生成。
- 产物（草案）：复诊摘要（并排事实）+ 问诊问题清单（判读留给医生）。
- 双主体注意：摘要导出自动过滤 private 项。

## 反推的页面树原则

- 两条以上流都经过的页 → 一级；只有单条流用的 → 二级；没有流经过的 → 不做。
- M1 结束时把每条流落到具体 `view.sub` 枚举，与 SCENARIOS S 编号互相引用。
